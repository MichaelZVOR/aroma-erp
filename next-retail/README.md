# Арома ERP

Установленная переходная версия — `C:/Aroma/next-retail`.
Запуск через обычный `C:/Aroma/Арома.exe`. Основной сайт —
`http://127.0.0.1:8788`, меню склада и продаж ведёт на новый Next.js
`http://127.0.0.1:8791`. Данные входа — `C:/Aroma/next-retail/data/Локальный вход.txt`.
Проверены вход и переход из основного меню к первоначальной настройке магазинов.
Подробный статус установки и ограничения синхронизации — в STORE-SALES.md.
Ниже сохранены команды разработки и предшествующий диагностический статус.

Каркас серверной версии. Этапы переноса описаны в [плане](docs/PLAN.md).

Локальный запуск на Node.js 24:

```text
npm ci
npm run local:prepare
npm run dev
```

Открыть `http://127.0.0.1:3000`. Доступ к рабочей базе добавляется на этапе переноса.

Новый модуль учёта описан в [STORE-SALES.md](docs/STORE-SALES.md). Страницы
`/sales` и `/stock` используют общие партии и движения. Перед первой работой
создаются два магазина с реальными названиями, затем вводится фактическая приёмка.
Локальный логин находится в игнорируемом файле `data/Локальный вход.txt`.
Это локальный проверочный вход одного администратора. Пользователи и 2FA
остаются отдельным этапом до публикации в интернете.

`npm run local:catalog -- <путь-к-копии.sqlite3>` переносит только карточки
и реквизиты БИФИТ. Источник открывается только для чтения. Поступления и продажи
в новую базу `data/retail.sqlite3` этот скрипт не создаёт. Каталог переносился
из снимка от 3 ноября 2026, поэтому перед рабочим запуском потребуется сверка
с актуальной базой. Не запускать импорт на рабочей базе вместо её копии.

Для БИФИТ доступны карточки CSV и заполнение его шаблона количественных остатков.
Сначала выберите один магазин. Шаблон берётся из отчёта остатков БИФИТ, затем
явно выбираются колонки идентификатора и количества. Идентификаторы и остальные
реквизиты сохраняются, отсутствующие в нашем учёте товары не обнуляются.
Перед реальным импортом требуется проверка в кабинете БИФИТ.

Проверено 26 тестами на отдельных базах. Проверка интерфейса пока не завершена.
В среде агента локальное соединение блокируется с `connect EACCES`, даже
при доступе к собственному тестовому HTTP-серверу. Рабочая установка не обновлялась.

Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.
Синтетические эталоны лежат в `tests/fixtures`. Рабочие данные и реальные эталоны
хранятся локально в `data`, которую Git игнорирует.
