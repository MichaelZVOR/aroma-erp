# Работа над Арома ERP

## Обязательная визуальная проверка — правило владельца от 07.11.2026

При каждой работе над интерфейсом проверять не только функции, но и гармоничность текста:
- ровные заголовки, подписи, цифры, отступы и выравнивание соседних элементов;
- знак ₽ не переносить отдельно от суммы или относящейся к нему подписи;
- денежные суммы показывать цельно, используя неразрывный пробел и при необходимости white-space: nowrap;
- выделять колонкам достаточную ширину; на узком экране использовать прокрутку таблицы, не обрезать значения;
- перед сдачей смотреть установленный экран в браузере и проверять переносы, симметрию и читаемость.
Это постоянный пункт проверки каждой интерфейсной задачи, а не разовая правка.

Стек: Next.js 16 (App Router) + TypeScript strict + Ant Design 6 + SQLite (better-sqlite3, Drizzle).
Один проект, один процесс. Python, PostgreSQL и отдельный бэкенд не добавлять.
План и бизнес-правила — в документе «Арома ERP — план переезда на Next.js» (docs/PLAN.md).

## Правила владельца

- ПЕРЕД КАЖДОЙ НОВОЙ ЗАДАЧЕЙ ИЗУЧАТЬ ГОТОВЫЕ РЕШЕНИЯ 1С, БИФИТ, МОЙСКЛАД И ЭВОТОР. ИСПОЛЬЗОВАТЬ ИХ ПРОВЕРЕННЫЕ СЦЕНАРИИ И ИНТЕРФЕЙСНЫЕ ПРИЁМЫ, А НЕ ПРИДУМЫВАТЬ ПРОЦЕСС ЗАНОВО.
- Сначала учитывать предоставленные владельцем скриншоты и официальную документацию. В плане записывать источник, выбранный сценарий и конкретные изменения. Отсутствующие в нашей задаче функции не копировать автоматически, финансовые правила менять только с согласования владельца.
- Менять только прямо запрошенный раздел и согласованный объём задачи.
- Не менять финансовые формулы и коэффициенты без явного согласования и примера расчёта.
- Не переименовывать товары и не подставлять альтернативные названия автоматически.
- Исходные названия, цены и реквизиты импорта брать из согласованного CSV.
- Не пересчитывать прошлые документы по текущим ценам справочника.
- Не добавлять Gold Apple / Aroma-Butik в поиск цен без нового запроса владельца.
- Не загружать в Git базу, продажи, закупочные цены, фото, реальные эталоны и секреты.

## Защита незавершённой работы

- Каждая форма и незавершённая операция во всех разделах должна защищать введённые данные при переходе между вкладками, категориями, страницами и при возврате назад. Выход возможен после успешного сохранения или явного отказа от изменений.
- При закрытии изменённой формы или переходе из неё показывай одно подтверждение с действиями «Продолжить работу» и «Выйти». После «Выйти» выполняй исходное действие сразу. Крестик редактируемой формы всегда показывает подтверждение. При переходе в другой раздел подтверждение требуется при несохранённых изменениях.
- В приёмке подтверждение относится к крестику окна «Добавить товар». После закрытия подбора переход в другой раздел выполняется сразу.
- Клик за пределами формы и Esc не должны закрывать редактируемую форму. Проверяй в браузере, что после отмены перехода сохраняются все поля и выбранные строки.

## Код

- page.tsx — Server Component (данные + проверка роли); antd — только в клиентском XxxView.tsx.
- Изменения — Server Actions с проверкой сессии и роли. Вход — только route handler /api/auth/*.
- Деньги — целые копейки в базе, арифметика только через src/domain/money (decimal.js).
- Формулы — чистые функции в src/domain с тестами на эталонах. Эталоны не править, чтобы тест прошёл.
- Даты в базе — UTC, на экране — часовой пояс магазина, формат ДД.ММ.ГГГГ.
- Состояние списков — в URL. Формы — отдельные страницы, модалки — только для коротких действий.
- Prettier, строка до 100 символов, понятные имена, LF. Без @ts-ignore, eslint-disable и пропущенных тестов.

## Проверка и выкладка

- Одна задача — одна ветка и один PR. Слияние только при зелёном CI.
- Финансовые и складские операции проверять на отдельной базе, интерфейс — в браузере.
- Рабочую базу не заменять тестовой. Перед деплоем копия базы делается автоматически.
- Деплой — только через GitHub Actions (DEPLOY.md). На сервере руками ничего не собирать и не править.
- В отчёте различать: написано / проверено тестами / проверено в браузере / выложено на сервер.
